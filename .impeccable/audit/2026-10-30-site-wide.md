# Site-wide technical audit

Date: 2026-10-30. Scope: shared navigation, shell, inquiry form, assistant, home, product catalog/detail, content loading, CSS and Vite configuration.

## Implementation integrity verdict

Pass with gaps. Shared semantic color tokens, type utilities, product-backed catalog navigation, reusable cards and MDX content establish a coherent system specific to this manufacturer. The bundled `impeccable detect --json src` returned `[]`. That result covers its deterministic rules, not accessibility conformance. Manual source inspection found the issues below, especially assistant token drift and incomplete modal behavior.

## Findings

### P1: Modal interfaces do not contain and restore keyboard focus

- Locations: `src/components/SiteNavbar.tsx:329`, `src/pages/ProductDetailPage.tsx:239`, `src/components/rag/JKFertilizersRAGChat.tsx:85`.
- Category: Accessibility and implementation integrity.
- Evidence: All three declare modal dialogs. The drawer only locks scrolling and handles Escape. The lightbox does likewise with arrow keys. The assistant focuses its input after opening. None implements a focus trap, background inertness while open, and focus restoration as a complete lifecycle. The drawer's `inert={!mobileOpen}` protects the closed drawer, not the background when open.
- Impact: Keyboard users can operate background content while a modal visually blocks it; drawer and lightbox users are not deliberately moved into the dialog.
- Standard: WAI-ARIA modal dialog keyboard pattern; WCAG 2.4.3 focus order risk. Runtime traversal remains to be checked.
- Recommendation: Use a shared accessible dialog primitive with initial focus, focus containment, background isolation, Escape handling, and trigger focus restoration.
- Suggested command: `$impeccable harden`.

### P1: Mobile chat submit button has no accessible name

- Location: `src/components/rag/JKFertilizersRAGChat.tsx:451`.
- Category: Accessibility.
- Evidence: The button contains an icon and `hidden sm:inline` text, without an aria-label. Below the small breakpoint the visible control has no text name.
- Impact: Screen-reader users cannot identify the send action on mobile.
- Standard: WCAG 4.1.2, Name, Role, Value.
- Recommendation: Give the button a persistent accessible name. Give the adjacent input an explicit label as well; it currently relies on its placeholder, which disappears during entry.
- Suggested command: `$impeccable harden`.

### P1: Product filter selection is only conveyed visually

- Location: `src/pages/ProductsPage.tsx:158`.
- Category: Accessibility.
- Evidence: Category buttons change styling from `isSelected`, without `aria-pressed` or an equivalent selected state.
- Impact: Assistive technology cannot tell which category currently filters the catalog.
- Standard: WCAG 4.1.2, Name, Role, Value.
- Recommendation: Use toggle buttons with `aria-pressed`, and announce the updated result count through a restrained status region.
- Suggested command: `$impeccable harden`.

### P1: Continuous product ticker lacks a pause control

- Location: `src/components/HomePage.tsx:479`.
- Category: Accessibility.
- Evidence: Both ticker tracks animate indefinitely over 35 seconds. No pause, stop, or hide control is implemented. Reduced-motion CSS stops the ticker for users with that preference, but other users cannot pause it.
- Impact: Motion competes with reading and makes ticker content harder to inspect.
- Standard: WCAG 2.2.2, Pause, Stop, Hide.
- Recommendation: Add a keyboard-operable pause control or render a static product strip. Retain the reduced-motion alternative.
- Suggested command: `$impeccable animate`.

### P2: Routes and article bodies load eagerly

- Locations: `src/App.tsx:11`, `src/lib/content.ts:24`, `src/lib/content.ts:103`, `src/data/products.ts:68`.
- Category: Performance.
- Evidence: All page components are static imports; product, blog and service MDX modules use eager globs. Image URL globs alone are not evidence that image bytes download immediately.
- Impact: Visitors to a single product also receive JavaScript for unrelated pages and content. The cost grows with the catalog and blog.
- Recommendation: Split route components and MDX bodies, keeping only required index metadata eager. Measure output size before and after. No bundle-size claim is made here because the build could not run.
- Suggested command: `$impeccable optimize`.

### P2: Offline installation precaches the full image inventory

- Location: `vite.config.ts:112`.
- Category: Performance.
- Evidence: Workbox precache globs include all emitted images and fonts, with a 20 MiB per-file allowance. Source content is about 19 MB and public assets about 8 MB; those directory sizes are not a measured precache payload.
- Impact: Once the service worker installs, visitors may download images for products and articles they never visit, consuming bandwidth and storage.
- Recommendation: Precache the minimum application shell and essential assets; use the existing bounded runtime image cache for galleries. Measure the generated precache manifest after dependencies are available.
- Suggested command: `$impeccable optimize`.

### P2: Reveal layers retain will-change after entering

- Location: `src/index.css:342`.
- Category: Performance.
- Evidence: All four reveal classes set `will-change: opacity, transform`; their visible states never reset it, although the default observer reveals only once.
- Impact: Long pages may retain unnecessary compositing resources after animations finish. Actual GPU allocation requires profiling.
- Recommendation: Remove the standing hint or apply it only during animation and clear it afterward.
- Suggested command: `$impeccable optimize`.

### P2: Explicit small mobile targets

- Locations: `src/components/SiteNavbar.tsx:355`, `src/components/rag/JKFertilizersRAGChat.tsx:284`.
- Category: Responsive design.
- Evidence: Drawer close is 36 by 36 CSS pixels. Chat close is a 20px icon with 6px padding, nominally 32 by 32. Both are below the audit's 44px target recommendation.
- Impact: Frequent dismiss actions require more precise tapping.
- Standard: 44px is an enhanced touch-target recommendation and WCAG 2.5.5 AAA size; these dimensions alone do not prove a WCAG 2.5.8 AA failure.
- Recommendation: Expand hit areas to at least 44 by 44 without enlarging the icons. Verify spacing and actual bounds in a browser.
- Suggested command: `$impeccable adapt`.

### P2: Assistant duplicates brand colors instead of using semantic tokens

- Locations: `src/components/rag/JKFertilizersRAGChat.tsx:212`, `src/index.css:269`.
- Category: Theming and implementation integrity.
- Evidence: The assistant repeatedly embeds hex colors already represented by brand and semantic tokens. A few isolated intentional literals elsewhere are not treated as a systemic finding.
- Impact: Brand or contrast corrections can update the site while leaving the assistant unchanged.
- Recommendation: Map assistant surfaces, text, borders, and actions to the existing semantic tokens. No dark-mode failure is asserted: a supported dark-mode product requirement was not established.
- Suggested command: `$impeccable polish`.

## Patterns and strengths

The main systemic gaps are modal behavior implemented separately, eager content loading, and assistant styles bypassing shared tokens. A clean detector result does not cover those concerns.

Preserve the skip link and main landmark, labeled inquiry fields, inline form errors with `role="alert"`, direct contact fallbacks, inert closed mobile drawer, existing Escape handling, lazy gallery images, responsive layout variants, and purposeful reduced-motion alternatives for reveals, the ticker and page entry. The audit did not find a global animation-duration kill switch.

## Recommended actions

1. `$impeccable harden`: modal focus lifecycle, chat naming, filter state.
2. `$impeccable animate`: ticker pause control.
3. `$impeccable optimize`: route/content splitting, precache scope, reveal hints.
4. `$impeccable adapt`: mobile hit areas and browser validation at narrow widths and text zoom.
5. `$impeccable audit`: rerun with installed dependencies and rendered desktop/mobile evidence; verify contrast, keyboard use, overflow and build output.
6. `$impeccable polish`: consolidate assistant tokens and finish after the functional fixes.
